# Testing

Developer reference for HaiCode's test suite. Build and run everything from the
repository root:

```bash
cmake -B build -S .
make -C build -j$(nproc)
ctest --test-dir build --output-on-failure
```

## Running one test binary

Each binary prints an `[OK]`/`[FAIL]` line per check and exits non-zero when
any check fails. `lib/` tests build to `build/lib/`, `gui/` tests to
`build/gui/`:

```bash
./build/lib/test_git_find
./build/gui/test_chat_view
```

## What each test covers

Rows are named by their CTest test name. For the `lib/` tests that is also the
binary name (`build/lib/test_<name>`); the three `gui/` tests drop the binary's
`test_` prefix (`chat_view` runs `build/gui/test_chat_view`).

## Adding a test

All tests use `/tmp` for scratch files and clean up after themselves.

To add a test for a new tool, create `lib/tests/test_<name>.cpp` and add two lines to `lib/CMakeLists.txt`:
```cmake
add_executable(test_<name> tests/test_<name>.cpp)
target_link_libraries(test_<name> haicode)
```
then register it in the `foreach(t ...)` block that feeds `add_test()` below the test targets, and add a row to the table above. All transitive deps (sqlite3, curl, be, root) are inherited from the `haicode` target — no manual `-l` flags needed. Use the `TEST_REQUIRE` macro from `tests/test_check.h` (not `assert`) for invariants that must hold in Release builds.
